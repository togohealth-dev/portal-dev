TogoHealthNew-Hire Machine Setup · Reference

Get your laptop
trail-ready

Brand-new Mac or PC to fully set up, sign in everywhere, and Claude running the rest — step by step, nothing skipped.

Works either machine — every command below shows a 🍎 Mac and 🪟 PC version. Pick your tab once; it'll remember it as you scroll.

Before you touch a terminal: ask Greg or Morgan for three things — a GitHub account added to the togohealth-dev org, a @togohealth.com Google account, and to be told when both are ready. Everything below assumes you have them.
Phase 1 · Get online
1
You

Unbox & sign in 🖥️

Turn on the laptop, connect to Wi-Fi, and let it finish any first-run system updates before installing anything.

🍎 Mac: sign in with your @togohealth.com Google account when prompted, or skip and do it in Chrome (next step).
🪟 PC: a Microsoft/local account is fine for Windows itself — your @togohealth.com identity lives in Chrome and Google, not Windows.

2
You

Install Chrome & sign in to Google Workspace 🌐

Download Chrome from google.com/chrome and install it — on both Mac and PC this is the same installer flow (download → open → drag/run).

Open Chrome, click your profile icon (top-right) → Sign in → use your @togohealth.com address. This one account is your identity for Gmail, Drive, Tailscale, and the project tracker.

3
You

Pin your terminal ⌨️

You'll live in this for the next hour, so keep it one click away.

🍎 Mac — Terminal: press ⌘Space, type Terminal, open it, then right-click its Dock icon → Options → Keep in Dock.
🪟 PC — PowerShell: click Start, type PowerShell, right-click Windows PowerShell → Pin to taskbar (or Pin to Start).

Phase 2 · Terminal bootstrappaste these one at a time — read what each does first
4
You, in the terminal

Package manager + Git 📦

This installs the tool that installs everything else.

# Command Line Tools (includes git)
xcode-select --install

# Homebrew
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
# Git (winget ships with Windows 10/11)
winget install --id Git.Git -e --source winget

# close and reopen PowerShell so PATH updates, then continue below
5
You, in the terminal

Node + GitHub CLI 🔧

brew install node gh
winget install --id OpenJS.NodeJS.LTS -e --source winget
winget install --id GitHub.cli -e --source winget

# close and reopen PowerShell again
6
You, in the terminal

Claude Code — same command, either machine 🤖

npm install -g @anthropic-ai/claude-code
claude --version
npm install -g @anthropic-ai/claude-code
claude --version

Claude Code is Node-based, so once Node is installed the install step is identical on Mac and PC.

7
You, in the terminal

Sign in to GitHub 🔐

gh auth login
# browser opens → log in with your GitHub account

gh auth refresh -h github.com -s workflow
gh auth login
# browser opens → log in with your GitHub account

gh auth refresh -h github.com -s workflow

That second command matters: without the workflow scope, Claude can't push certain project files later and the push fails with a confusing permission error.

Phase 3 · Claude everywhere + passkeys
8
You

Sign in to all three Claude surfaces 🧠

  • Claude Desktop app — download from claude.ai/download, sign in with your work account.
  • Claude on the web — in Chrome, sign in at claude.ai. Claude Code on the web lives at claude.ai/code.
  • Claude for Chrome — install the sidebar extension, pin it, sign in with the same account. Only grant it access on sites you actually use it on.

Same account everywhere — sessions and history line up no matter which one you open.

9
You

Turn on passkeys 🔑

Passkeys use your laptop's own fingerprint/face sensor instead of typing a code every time.

🍎 Mac: Touch ID is usually already on ( → System Settings → Touch ID & Password).
🪟 PC: turn on Windows Hello ( → Settings → Accounts → Sign-in options) — fingerprint, face, or a PIN.

⚠️
You'll set up TWO separate passkeys, don't mix them up: one for your Google/GitHub identity (whenever a site asks), and a second one later for the local EMR sandbox login (Phase 5, below) — that one only exists on your machine and has nothing to do with Google.
Phase 4 · Hand it to Claude
10
You + Claude

Copy the setup prompt, start fresh 📋

  • Open the project tracker → 📚 Developer Reference Projects → "New-hire machine setup — Claude Code prompt."
  • Click Copy Prompt.
  • In your terminal, run claude to open a brand-new session and paste the whole thing in.

That prompt walks Claude (and you) through cloning the repos, wiring up the always-on local EMR, and joining the tracker — in order, checking each step before moving on.

🚫
Claude will pause at every login, password, and consent screen and hand it to you. Never let it type a password or accept an invite on your behalf — that's the one hard rule in that whole prompt.
11
You

Your localhost login — a new account + passkey 🩺

Partway through, Claude will have you open localhost:3000 for the first time. This is a separate account from Google/GitHub — it's your login for the sandbox EMR itself.

Click Forgot your password? → type in your @togohealth.com email → a 6-digit code arrives → set a password → sign in → enroll Touch ID / Windows Hello as your second passkey (the "MFA" one from Phase 3).

📧
If the code never arrives, that's a one-line fix in your local backend's email setup — tell Claude and it'll sort it out before you try again. Don't keep re-clicking "resend."

Good habits from day one

Small things that save you a confusing afternoon later.

🔑 Two different passkeys

Google/GitHub passkey ≠ localhost EMR passkey. Same finger, two separate accounts — don't assume enrolling one enrolls both.

🚫 Claude never types your password

Logins, invites, and consent screens are always yours to click — in setup and in every session after.

🙋 Optional access is opt-in

Tailscale and SEGE aren't part of default setup. If you need either, ask Greg or Morgan first — don't try to self-serve your way in.

🏷️ Name your sessions

"TogoHealth EMR Project Tracker," "SEGE Command Center," and one per project. A named session is one you can actually find again tomorrow.

📑 Bookmark all three environments

Alpha, beta, and gamma look almost identical — a bookmarks bar with all three visible stops you from testing on the wrong one.

📧 Localhost email issues are common

If the reset code never arrives, it's a known, one-line fix in the backend's email config — mention it to Claude rather than clicking resend a dozen times.

🪟 PC vs 🍎 Mac — same destination

Different install commands, identical result: git, GitHub CLI, Node, and Claude Code all working from your terminal.
