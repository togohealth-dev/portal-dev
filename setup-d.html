Phase 3 · Lane discipline — the part that matters
🧭

Keep the lanes apart

  • ~/claude/sege/ is its own lane with its own rules; the global router in ~/.claude/CLAUDE.md also applies.
  • Never write SEGE content into an EMR repo, and never write EMR code under the SEGE lane. No SEGE issues in emr-beta.
  • Private staffing data stays in sege-staffing. It does not get copied into the dashboard repo, an issue, a PR, or a chat.
  • Cross-lane questions are fine — “how does the SEGE tracker label things versus the portal tracker?” Cross-lane files are not.
✅
If SEGE work is all you do, open your sessions in ~/claude/sege/ — not ~/claude, which is a container and loads no lane rules at all.

Four rules for the SEGE lane

The first one is about real people’s data. The rest keep the two products from bleeding into each other.

🔒 The PII grant is separate on purpose

sege-staffing holds real onboarding data about real people. It is a second, deliberate grant — treat being given it as a responsibility, not a convenience.

🚫 No empty lane folders

Create ~/claude/sege/ only after access lands. An empty lane that loads rules is a trap for your future self.

🧭 One lane per session

Open the session in the lane the work belongs to. A session in ~/claude loads nothing and will happily write to the wrong tree.

🚧 The lane file needs committing

Until the SEGE CLAUDE.md lives in sege-command, every new SEGE user sets it up by hand. Worth fixing once.
