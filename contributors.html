Method & honesty notes

Hours formula: 1.5h fixed (branch setup, localhost run-through, PR write-up, tracker move) + (effective lines + 0.35×deletions) ÷ 55 lines/hr + 0.25h per changed file + 0.2h per commit beyond the second.

Effective lines discount repeated boilerplate. An added line that exactly duplicates another added line in the same PR counts at 25%, because writing the 25th identical form field is not the same work as the first. This matters a lot on form-heavy diffs — #141 is 47% duplicate lines (863 raw → 528 effective, 18h → 12h) and #191 is 41% (127 → 82, 5.5h → 4.5h).

Attribution is by PR author, and that is imperfect. Commit authorship could not be used at all — 77 of 110 commits in this dataset are recorded as invalid-email-address (an unconfigured git identity), so they map to no GitHub account.

⚠ All code-sync PRs are excluded as upstream work. /pull-pr-code-only imports a diff from togohealth-dev and rewrites authorship to whoever ran it, so the importer is recorded as the author and the real provenance is destroyed at import. 13 of the 22 measured PRs contain a code-sync commit — #20, #50, #51, #52, #54, #55, #56, #57, #58, #123, #136, #151, #174. Since git cannot say who wrote that code, all thirteen are treated as Scott’s and none appear here. That is the single biggest reason these totals are small: only 9 of the 22 measured projects were authored directly in this repo.

Six projects are floors, not point estimates. Where a linked PR contains only migrations or a very small diff relative to the project’s stated scope, the real build time is higher than shown.

The β line is nearly empty on purpose — that is a real process gap, not missing data. Stage dates come from GitHub’s own label history, which covers alpha-ready on 14 of 16 projects and γ production on 16 of 16, but Beta-Version on only 3 of 16. Projects are being marked γ straight from alpha without ever carrying status:beta-version, so there is no date to plot. The tracker now stamps every stage date into the issue body as the button is pressed, so this fills in from here forward.

Scott is excluded from this summary. He reviews and gatekeeps rather than being counted as a build contributor here, so the six completed projects whose PRs he opened (#50, #52, #54, #55, #57, #58 — 55.5h) are not shown.

Nineteen completed projects are missing entirely — the early batch (#59–#72 and others) has no linked PR, so there is no code to measure. Of the 22 that do, 13 are code syncs, leaving the 9 shown here.
