🚫

🧭

Three rules that make lanes worth it

  • Worktrees go in ~/claude/togo/togo-emr/wt/, never in your home directory — forty loose worktrees make the folder picker useless.
  • The containers are not lanes. ~, ~/claude and ~/claude/togo just hold things; a session opened in one loads no rules at all.
  • Never write one lane’s files into another lane’s tree.

brew link --force libpq

  --no-default-features --features rustls,postgres
🪓

The four traps — each one bit a real machine

  • docker-compose is a separate formula. brew install docker gives only the CLI; with no compose plugin docker compose up prints usage and exits 0 — a script “succeeds” while the database never starts.
  • libpq is keg-only. Without brew link --force libpq, psql stays off PATH and the keep-alive script aborts.
  • The formula is rustup, not rustup-init. Then rustup default stable — installing rustup does not create a toolchain.
  • sqlx-cli applies the migrations your login depends on.
✅
You do not have to do these by hand — machine-setup/install.sh opens with a preflight that installs and verifies every one and reports what is missing.

Phase 6 · A localhost login that actually works
🔄

One idempotent command

Fully self-contained: local Docker Postgres (:5434, sandbox data) → Rust backend → Next.js frontends. No gcloud, no Cloud SQL, nothing shared.

cd ~/claude/togo/togo-emr/strategy-sessions-repo && git pull
bash machine-setup/bootstrap-dev-login.sh
cd ~/claude/togo/togo-emr/strategy-sessions-repo && git pull
bash machine-setup/bootstrap-dev-login.sh

It asks for your @togohealth.com email and does the rest: Colima and the sandbox Postgres up, portal/backend/.env written, the mail password fetched from Secret Manager, migrations applied, a seeded provider row linked to a local_auth account, and the launchd keep-alive installed.

🔁
It is idempotent. If a step fails, fix what it names and run the whole thing again — do not try to hand-finish the remaining steps.
🔐

Nothing here is hand-delivered

  • Your .env is generated from a template in the repo, not from someone else’s machine.
  • Login codes are real email to your own inbox, from the shared support@togohealth.com mailbox — the same path production uses.
  • Your login backend is yours alone — name, database and port derive from your email, so parallel worktrees never churn each other’s password.
  • The frontend finds it through a gitignored portal/web/.env.local. Never edit forceProd.
🔒
The mailbox password is the one true secret. Claude may run the bootstrap that fetches it, but must never print it into the session. If the fetch 403s, ask Greg or Scott for secretAccessor on support-mailer-password.
🚪

[YOU]

localhost:3000 → Forgot your password? → your @togohealth.com email → the 6-digit code arrives in your inbox → set a password → register a passkey (Touch ID) for MFA.

🔵
The tab icon tells you which environment you are looking at. Localhost shows Tlh, beta Tβ, alpha T·α, and production the plain Togo mark — so a stray tab is never mistaken for production. Nothing to install or edit: the mark ships in the code. If localhost shows Tβ instead, your branch simply predates the change — merge main.

If it does not work, the failure names itself:

  • A FAIL line from the bootstrap says exactly what to fix.
  • missing required env var(s) — config.rs gained a variable the template lacks. Add it to .env, then add it to the template so the next hire never sees it.
  • 404 on /auth/* — the backend build predates local_auth. Rebuild; do not work around it.
  • “Not authorized with any role” — the seed did not link your professional row to a local_auth account.

Six rules Claude is also told

These are in the prompt, but they outlive the setup — they apply to every session you ever run here.

🔒 Never invent or commit a secret

Your dev .env ships dev-placeholder for every vendor key. Real values come from Secret Manager, per person and revocable — never from a teammate’s laptop, an issue, or a chat.

🧠 AI on PHI means OpenAI

TogoHealth has a signed BAA with OpenAI, so it is the approved provider. Server-side (Rust backend) only, minimum-necessary PHI, and a clinician confirms every write.

🗃️ Localhost is sandbox-only

Never point it at the production database. PHI stays on the Mac mini.

🔥 Do not touch Firebase

Auth is MFA. Firebase is being removed — treat it as frozen. Persistent state goes in Postgres.

🗄️ One shared database across α/β/γ

Each environment has its own frontend and backend; only the DATABASE is shared. So a test row shows up in production the moment it exists — gate one that would confuse real users.
